## 第一部分 认识组件库仓库

### 1.1 仓库是做什么的

组件库是一个独立的 Git 仓库，存放 App 前端和网页前端共用的组件与设计规范。你在 HTML 设计稿里定义的视觉样式，会在这里变成一个个 `.vue` 组件文件。团队成员做页面时，先来这里找现成组件用，不用每次手写样式。

### 1.2 目录结构

仓库由组长尹辰已经初始化好，结构如下：

```
aistock-component-lib/
├── src/
│   ├── components/        # 你写的组件都放这里（每个 .vue 文件是一个组件）
│   ├── styles/
│   │   └── variables.scss # Design Token 设计变量（颜色、字号、间距等）
│   └── index.ts           # 统一导出入口（做完的组件在这里登记）
├── dev/                   # 本地预览环境
│   ├── App.vue            # 预览页面（引入组件看效果）
│   ├── main.ts            # 预览环境入口
│   └── global.scss        # 预览环境基础样式
├── design/                # 你的 HTML 设计稿放这里
├── docs/
│   └── 组件库搭建教程.md   # 本教程
├── AGENTS.md              # AI 开发助手调用指引
├── package.json           # 项目配置和依赖清单
├── vite.config.ts         # 预览环境配置
├── tsconfig.json          # TypeScript 配置
└── README.md              # 仓库说明
```

你主要在三个地方工作：

- `src/components/` — 写组件的地方，这是你的核心工作区
- `src/index.ts` — 每做完一个组件，在这里登记导出
- `dev/App.vue` — 想看组件效果时，在这里引入组件预览

### 1.3 技术栈说明

| 技术 | 作用 | 你需要了解的程度 |
|------|------|----------------|
| Vue 3 | 组件框架，每个组件是一个 `.vue` 文件 | 核心要掌握 |
| TypeScript | 给代码加类型标注，让编辑器能提示错误 | 照着模板写就行 |
| SCSS | 样式预处理器，支持变量和嵌套 | 核心要掌握 |
| rpx | uni-app 的尺寸单位，自动适配不同屏幕 | 核心要掌握 |
| Vite | 本地预览工具，启动后能实时看组件效果 | 会用命令即可 |

### 1.4 组件库和前端项目的关系

组件库本身不是 App，它只提供组件文件。App 前端项目（`aistock-app-frontend`，基于 uni-app）会引用组件库里的 `.vue` 文件，在自己的页面里使用。

因为 App 前端用 uni-app 框架，组件必须按 uni-app 规范写：用 `view`/`text` 标签（不用 `div`/`span`）、用 `rpx` 单位（不用 `px`）。这样写出来的组件，在 App、H5、小程序上都能正常显示。

本地预览环境（`dev/`）已经配置好，会自动把这些 uni-app 规范转换成浏览器能识别的格式，让你不用装完整的 uni-app 工具链就能看到效果。

### 1.5 关键概念 rpx

rpx 是 uni-app 的响应式像素单位。在 750px 宽的设计稿上，`1rpx = 1px`。在不同屏幕上会自动缩放，所以用 rpx 写的组件在所有手机上比例一致。

简单记：**所有尺寸都用 rpx，不要用 px**。设计稿上量出来的像素值，直接写成 rpx 就行。本地预览环境会自动把 rpx 转成浏览器能显示的单位。

## 第二部分 本地环境搭建与预览

### 2.1 安装 Node.js 和 pnpm

如果电脑上还没装 Node.js，打开浏览器访问 `https://nodejs.org`，下载 **LTS 版本**，双击安装，一路下一步。

装完后按 `Win + R`，输入 `cmd` 回车打开命令行，输入 `node -v` 验证。显示版本号就说明装好了。

接着装 pnpm（包管理工具），在命令行输入：

```
npm install -g pnpm
```

装完输入 `pnpm -v` 验证。

### 2.2 安装 VS Code 和插件

VS Code 是写代码的编辑器。访问 `https://code.visualstudio.com` 下载安装。

装完打开 VS Code，点左侧扩展图标（四个方块），搜索并安装：

- **Vue - Official**（Vue 官方插件，写 Vue 代码必备）
- **SCSS Formatter**（格式化 SCSS 样式）

### 2.3 克隆仓库并安装依赖

用你顺手的 Git 工具（GitHub Desktop、VS Code 自带 Git、或命令行都行），把组件库仓库克隆到本地。建议克隆到 `D:\aistock\aistock-component-lib`，和前端项目放一起方便对照。

克隆完后，用 VS Code 打开这个文件夹（`File` → `Open Folder`）。

在 VS Code 里打开终端（顶部菜单 **Terminal** → **New Terminal**），输入：

```
pnpm install
```

这一步会下载项目需要的所有第三方库，可能要等一两分钟。看到最后一行没有红色报错就说明成功了。

### 2.4 启动本地预览

在终端里输入：

```
pnpm dev
```

终端会显示一个本地网址（类似 `http://localhost:5173`），按住 Ctrl 点击它，浏览器会打开预览页面。你会看到一个「AiStock 组件库预览」的页面。

这个页面就是 `dev/App.vue`。以后你想看某个组件的效果，就在 `dev/App.vue` 里引入它，保存后浏览器会自动刷新显示最新效果。

> 预览环境开着的时候不要关闭终端窗口。关了终端预览就停了。要停止预览，在终端里按 `Ctrl + C`。

## 第三部分 Design Token 设计规范

Design Token 是一套统一的样式变量。所有组件的颜色、字号、间距都必须用这些变量，不能写死具体数值。这样做的好处是：以后想调整全局风格，只改变量就行，不用一个个组件改。

这些变量定义在 `src/styles/variables.scss` 里。下面是完整规范，你写组件时要对照着用。

### 3.1 颜色规范

| 变量名 | 值 | 用途 |
|--------|-----|------|
| `$brand-color` | `#4d7cfe` | 品牌主色（按钮、链接、顶栏渐变） |
| `$brand-color-secondary` | `#6366f1` | 品牌辅助色（渐变终点） |
| `$brand-gradient` | `linear-gradient(135deg, #4d7cfe, #6366f1)` | 品牌渐变背景 |
| `$success-color` | `#22c55e` | 成功/正向 |
| `$warning-color` | `#f59e0b` | 警告 |
| `$error-color` | `#f43f5e` | 错误/危险 |
| `$bg-color` | `#f5f7fb` | 页面背景 |
| `$bg-color-grey` | `#ffffff` | 卡片背景 |
| `$text-color-title` | `#1a1d24` | 标题文字（最深） |
| `$text-color-secondary` | `#6b7280` | 次要文字（描述、副标题） |
| `$text-color-tertiary` | `#9ca3af` | 辅助文字（时间、提示） |
| `$border-color` | `#e5e7eb` | 主边框 |

### 3.2 涨跌色规范（A 股专用）

A 股是「红涨绿跌」，和欧美相反，这点要特别注意。

| 变量名 | 值 | 用途 |
|--------|-----|------|
| `$stock-up-color` | `#f43f5e` | 上涨（红色） |
| `$stock-down-color` | `#22c55e` | 下跌（绿色） |
| `$stock-flat-color` | `#9ca3af` | 平盘（灰色） |

### 3.3 字号规范

只有 6 个字号档位，不要自创其他大小。

| 变量名 | 值 | 用途 |
|--------|-----|------|
| `$font-size-xs` | `20rpx` | 标签、辅助文字 |
| `$font-size-sm` | `22rpx` | 次要文字 |
| `$font-size-base` | `26rpx` | 正文 |
| `$font-size-lg` | `30rpx` | 卡片标题 |
| `$font-size-xl` | `34rpx` | 页面标题 |
| `$font-size-xxl` | `48rpx` | 大标题 |

### 3.4 间距规范

只有 4 个间距档位。

| 变量名 | 值 | 用途 |
|--------|-----|------|
| `$spacing-xs` | `8rpx` | 紧凑间距 |
| `$spacing-sm` | `16rpx` | 小间距 |
| `$spacing-base` | `24rpx` | 标准内边距 |
| `$spacing-lg` | `32rpx` | 大间距 |

### 3.5 圆角规范

| 变量名 | 值 | 用途 |
|--------|-----|------|
| `$radius-xs` | `8rpx` | 小标签 |
| `$radius-sm` | `12rpx` | 小卡片、按钮 |
| `$radius-base` | `16rpx` | 标准卡片 |
| `$radius-lg` | `20rpx` | 大卡片 |
| `$radius-pill` | `9999rpx` | 胶囊按钮 |

### 3.6 阴影规范

| 变量名 | 值 | 用途 |
|--------|-----|------|
| `$shadow-base` | `0 2rpx 8rpx rgba(0,0,0,0.04)` | 轻微阴影 |
| `$shadow-card` | `0 2rpx 12rpx rgba(0,0,0,0.06)` | 卡片阴影 |
| `$shadow-strong` | `0 4rpx 16rpx rgba(77,124,254,0.3)` | 品牌色阴影 |

### 3.7 在组件里怎么用变量

预览环境已经全局引入了变量文件，你在 `<style>` 里可以直接用变量名，不用再手动 import：

```scss
<style lang="scss" scoped>
.my-card {
  background: $bg-color-grey;
  border-radius: $radius-base;
  padding: $spacing-base;
  box-shadow: $shadow-card;

  .title {
    font-size: $font-size-lg;
    color: $text-color-title;
  }
}
</style>
```

> 禁止在组件里写死颜色值（比如 `color: #1a1d24`），必须用变量（`color: $text-color-title`）。

## 第四部分 从 HTML 设计稿到组件

这一部分是核心。你的 HTML 设计稿里定义了组件长什么样，现在要把它们翻译成 `.vue` 组件文件。

### 4.1 把 HTML 设计稿放进仓库

把你做好的 HTML 设计文件放到仓库的 `design/` 目录下（比如 `design/design-system.html`），提交并推送到 GitHub（参考第六部分的 PR 流程）。

这样团队成员也能看到你的设计稿，对照着理解组件效果。

### 4.2 HTML 和 Vue 组件的对应关系

HTML 设计稿里一个独立的视觉模块，对应一个 Vue 组件。比如设计稿里有一个「卡片」样式，就做一个 `Card.vue` 组件。

对应规则：

| HTML 设计稿 | Vue 组件 |
|------------|---------|
| `<div>` | `<view>` |
| `<span>` / `<p>` | `<text>` |
| `<img>` | `<image>` |
| CSS 类名 | SCSS 类名（加 `as-` 前缀） |
| 写死的颜色/尺寸 | Design Token 变量 |

> 为什么不用 `div` 和 `span`？因为组件要被 App 前端（uni-app）使用，小程序不认识 `div`，但都认识 `view` 和 `text`。统一用 `view`/`text` 能一套代码跑所有端。

### 4.3 手把手做一个卡片组件

假设你的 HTML 设计稿里有一个卡片，长这样：

```html
<div class="card">
  <div class="card-header">
    <span class="card-title">趋势股评分</span>
    <span class="card-subtitle">技术面分析</span>
  </div>
  <div class="card-body">
    内容放在这里
  </div>
</div>
```

对应的 CSS：

```css
.card {
  background: #ffffff;
  border-radius: 16rpx;
  padding: 24rpx;
  box-shadow: 0 2rpx 8rpx rgba(0, 0, 0, 0.04);
}
.card-title {
  font-size: 30rpx;
  font-weight: 600;
  color: #1a1d24;
}
```

现在把它翻译成 Vue 组件。在 `src/components/` 下新建文件 `Card.vue`：

```vue
<template>
  <view class="as-card">
    <view v-if="title || $slots.header" class="as-card-header">
      <slot name="header">
        <text class="as-card-title">{{ title }}</text>
        <text v-if="subtitle" class="as-card-subtitle">{{ subtitle }}</text>
      </slot>
    </view>
    <view class="as-card-body">
      <slot />
    </view>
  </view>
</template>

<script setup lang="ts">
withDefaults(defineProps<{
  title?: string
  subtitle?: string
}>(), {
  title: '',
  subtitle: ''
})
</script>

<style lang="scss" scoped>
.as-card {
  background: $bg-color-grey;
  border-radius: $radius-base;
  padding: $spacing-base;
  box-shadow: $shadow-base;
}

.as-card-header {
  display: flex;
  align-items: center;
  margin-bottom: $spacing-sm;
}

.as-card-title {
  font-size: $font-size-lg;
  font-weight: 600;
  color: $text-color-title;
}

.as-card-subtitle {
  font-size: $font-size-base;
  color: $text-color-secondary;
  margin-left: 12rpx;
}

.as-card-body {
  width: 100%;
}
</style>
```

对照说明：

- `<template>` 里把 `div` 换成 `view`，`span` 换成 `text`
- 类名从 `card` 改成 `as-card`（加 `as-` 前缀，避免和别人冲突）
- 写死的颜色换成变量：`#ffffff` → `$bg-color-grey`，`#1a1d24` → `$text-color-title`
- 写死的尺寸换成变量：`16rpx` → `$radius-base`，`24rpx` → `$spacing-base`
- `title` 和 `subtitle` 做成 Props，让别人用的时候能传值，不用写死
- `<slot />` 是「内容占位符」，别人用这个卡片时，卡片里放什么内容由他决定

### 4.4 在预览环境里看效果

做完组件后，打开 `dev/App.vue`，引入这个组件看效果：

```vue
<template>
  <view class="dev-container">
    <view class="dev-section">
      <text class="dev-section-title">Card 组件</text>
      <Card title="趋势股评分" subtitle="技术面分析">
        <text>这里是卡片内容</text>
      </Card>
    </view>
  </view>
</template>

<script setup lang="ts">
import Card from '@/components/Card.vue'
</script>
```

保存后，浏览器会自动刷新，你就能看到卡片效果了。调整组件代码，保存，效果实时更新。

### 4.5 登记导出组件

预览效果满意后，在 `src/index.ts` 里登记这个组件，让团队能统一引用：

```ts
export { default as Card } from './components/Card.vue'
```

每做完一个组件，都在这里加一行导出。

### 4.6 手把手做一个按钮组件

再看一个带交互的例子。HTML 设计稿里的按钮：

```html
<button class="btn btn-primary">确认</button>
```

翻译成 `Button.vue`：

```vue
<template>
  <view
    :class="['as-btn', `as-btn--${type}`, { 'as-btn--disabled': disabled }]"
    @tap="handleTap"
  >
    <text class="as-btn-text"><slot /></text>
  </view>
</template>

<script setup lang="ts">
const props = withDefaults(defineProps<{
  type?: 'primary' | 'default' | 'danger' | 'text'
  disabled?: boolean
}>(), {
  type: 'primary',
  disabled: false
})

const emit = defineEmits<{ (e: 'click'): void }>()

function handleTap() {
  if (props.disabled) return
  emit('click')
}
</script>

<style lang="scss" scoped>
.as-btn {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  border-radius: $radius-sm;
  padding: $spacing-sm $spacing-lg;

  &--primary {
    background: $brand-color;
    color: #ffffff;
  }

  &--default {
    background: $bg-color;
    color: $text-color-title;
    border: 1rpx solid $border-color;
  }

  &--danger {
    background: $error-color;
    color: #ffffff;
  }

  &--text {
    background: transparent;
    color: $brand-color;
  }

  &--disabled {
    opacity: 0.5;
  }

  &:active {
    opacity: 0.8;
  }
}

.as-btn-text {
  font-size: $font-size-base;
}
</style>
```

这个组件多了两个知识点：

- **Props 类型限定**：`type` 只能传 `'primary'`、`'default'`、`'danger'`、`'text'` 四个值之一，传别的编辑器会报错
- **事件**：`@tap` 是点击事件（uni-app 用 `@tap` 不用 `@click`），点一下会触发 `click` 事件，用的人监听 `@click` 就能响应

## 第五部分 组件开发规范

做完上面两个例子，你已经掌握了基本方法。这一部分把规范说清楚，照着做就不会出错。

### 5.1 命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 组件文件名 | 大驼峰，一个组件一个文件 | `Card.vue`、`EmptyState.vue` |
| 组件类名 | 统一 `as-` 前缀 + 短横线连接 | `as-card`、`as-btn--primary` |
| Props 名 | 小驼峰 | `title`、`showHeader` |
| 事件名 | 小写连字符 | `@click`、`@change` |

### 5.2 标签规范

组件要被 uni-app 项目使用，必须用以下标签，不能用 HTML 原生标签：

| 用途 | 用这个 | 不要用 |
|------|--------|--------|
| 容器/区块 | `<view>` | `<div>` |
| 文字 | `<text>` | `<span>` / `<p>` |
| 图片 | `<image>` | `<img>` |
| 输入框 | `<input>` | `<input>`（一样） |
| 滚动区域 | `<scroll-view>` | 自己写 overflow |

### 5.3 Props 定义规范

所有可配置的内容都做成 Props。用 `withDefaults(defineProps<{}>(), {})` 的写法：

```vue
<script setup lang="ts">
withDefaults(defineProps<{
  title?: string              // 可选，字符串
  count?: number              // 可选，数字
  type?: 'primary' | 'danger' // 可选，限定值
  showHeader?: boolean        // 可选，布尔
}>(), {
  title: '',                  // 默认空字符串
  count: 0,                   // 默认 0
  type: 'primary',            // 默认 primary
  showHeader: true            // 默认 true
})
</script>
```

> 带 `?` 表示可选。每个可选 Props 都要在 `withDefaults` 第二个参数里给默认值。

### 5.4 样式规范

- `<style lang="scss" scoped>` 必须加 `scoped`，防止样式污染别的组件
- 所有颜色用变量，不写死
- 所有尺寸用 rpx，不用 px
- 嵌套写法用 SCSS 的 `&` 语法

### 5.5 图标规范

项目里禁用 emoji 表情符号，所有图标用 `SvgIcon` 组件加载 SVG 文件。

SVG 图标文件放在 `src/static/assets/icons/` 下（命名用短横线，如 `bell-line.svg`）。使用方式：

```vue
<template>
  <SvgIcon name="bell-line" size="36rpx" color="#9ca3af" />
</template>

<script setup lang="ts">
import SvgIcon from '@/components/SvgIcon.vue'
</script>
```

`name` 是图标文件名（不带 `.svg` 后缀），`size` 控制大小，`color` 控制颜色。

## 第六部分 GitHub 协作与 PR 流程

组件库采用 Pull Request（PR）流程：你在自己的分支上开发组件，开发完后发一个 PR 请求，尹辰检查通过后合并到主分支 `main`。这样能保证主分支始终是稳定可用的状态。

这一部分详细讲整个流程。

### 6.1 开工前：拉取最新代码

每次开始工作前，先切到 `main` 分支，拉取最新代码，避免和别人的修改冲突。

用 VS Code 终端操作：

```
git checkout main
git pull
```

用 GitHub Desktop 的话：左上角选 `main` 分支，点 **Fetch origin**，有更新就点 **Pull origin**。

### 6.2 创建开发分支

不要在 `main` 上直接改。为每个组件新建一个分支，分支名用 `feat/组件名` 格式：

```
git checkout -b feat/card
```

用 GitHub Desktop：左上角点当前分支名 → **New branch** → 输入 `feat/card` → **Create branch**。

> 分支名规范：`feat/组件名`（新增组件）、`fix/组件名`（修复组件问题）、`docs/说明`（改文档）。用英文小写，单词之间用短横线。

### 6.3 开发并提交

在分支上写组件代码（参考第四、五部分）。写完后提交：

```
git add src/components/Card.vue
git commit -m "feat: 新增 Card 卡片组件"
```

> 提交信息规范：开头用 `feat:`（新增）、`fix:`（修复）、`docs:`（文档）、`style:`（样式调整），后面一句话说清楚改了什么。用 GitHub Desktop 的话，在 Summary 框里填 `feat: 新增 Card 卡片组件`。

> 用 `git add 具体文件路径`，不要用 `git add .` 一次性加所有文件，避免误提交无关改动。

### 6.4 推送分支到 GitHub

```
git push -u origin feat/card
```

第一次推送这个分支时要加 `-u origin`，以后再推送只需 `git push`。

用 GitHub Desktop：点顶部的 **Push origin** 按钮即可，它会自动处理。

### 6.5 在 GitHub 网页发起 Pull Request

这是 PR 流程的关键一步。推送完成后，打开浏览器访问组件库的 GitHub 仓库页面。

1. 仓库页面顶部会出现一条黄色提示「`feat/card` had recent pushes」，点右边的 **Compare & pull request** 按钮
2. 如果没出现这条提示，点页面上方的 **Pull requests** 标签 → 点绿色 **New pull request** 按钮 → 在「compare」下拉框里选你的分支 `feat/card`
3. 进入 PR 创建页面后，填写：
   - **标题**：一句话说明做了什么，比如「feat: 新增 Card 卡片组件」
   - **描述**：简单说明这个组件的作用、改了哪些文件。如果是新增组件，可以贴一张预览截图
4. 确认右边的目标分支是 `main`（base: main ← compare: feat/card）
5. 点绿色的 **Create pull request** 按钮

PR 创建成功后，页面会显示这个 PR 的状态。这时候等尹辰来检查（review）。

### 6.6 等待 review 并处理反馈

尹辰检查你的 PR 后，可能会有几种情况：

**情况一：直接通过合并**
尹辰点 **Merge pull request** 按钮，PR 合并到 `main`。你会收到 GitHub 的邮件通知。合并完成后，这个分支的工作就完成了。

**情况二：提出修改意见**
尹辰会在 PR 页面的「Files changed」里给某些代码行留评论，提出修改建议。你会收到邮件通知。这时：

1. 不要在 GitHub 上改，回到本地 VS Code，切到你的开发分支 `feat/card`
2. 根据评论修改代码
3. 提交并推送（`git add` → `git commit` → `git push`）
4. 推送后 PR 页面会自动更新，显示你的新改动，尹辰会继续看

**情况三：有冲突**
如果尹辰在 `main` 上改了和你冲突的文件，GitHub 页面会显示「This branch has conflicts that must be resolved」。这时：

1. 在本地切到 `main`，拉取最新：`git checkout main` → `git pull`
2. 切回你的分支：`git checkout feat/card`
3. 合并 main：`git merge main`
4. 如果有冲突，VS Code 会标出冲突文件。打开文件，手动选择保留哪些内容（VS Code 会提供「Accept Current」、「Accept Incoming」等按钮）
5. 解决完冲突后，提交并推送：`git add .` → `git commit` → `git push`
6. PR 页面的冲突提示会自动消失

如果冲突不知道怎么解决，截图发给尹辰，不要瞎选。

### 6.7 合并后：清理本地分支

PR 合并完成后，你的开发分支就没用了，可以删掉，保持本地干净：

```
git checkout main
git pull
git branch -d feat/card
```

第一行切回 main，第二行拉取最新（包含你刚合并的改动），第三行删除本地开发分支。远程分支会在合并 PR 时自动提示删除，点一下就行。

### 6.8 整个流程速查

```
1. git checkout main && git pull        # 拉最新
2. git checkout -b feat/card            # 建分支
3. 写组件代码
4. git add src/components/Card.vue      # 暂存
5. git commit -m "feat: 新增 Card 组件"  # 提交
6. git push -u origin feat/card         # 推送
7. GitHub 网页发 PR                     # 发起合并请求
8. 等尹辰 review                        # 等检查
9. 合并后 git checkout main && git pull && git branch -d feat/card  # 清理
```

## 第九部分 常见问题

### 9.1 改了组件但预览页面没变化

检查三件事：

1. 是不是忘了保存文件（VS Code 里 `Ctrl + S`）
2. `dev/App.vue` 里是不是正确 import 了这个组件
3. 终端里的预览进程是不是还开着（关了就 `pnpm dev` 重新启动）

### 9.2 样式没生效

检查 `<style>` 标签有没有写 `lang="scss" scoped`。预览环境已经全局引入了变量文件，你不需要手动 import，直接用 `$brand-color` 这样的变量名就行。

### 9.3 编辑器报红色波浪线

把鼠标移到红线上看提示。常见原因：

- Props 拼写错误
- 变量名写错（变量名在 `src/styles/variables.scss` 里查）
- import 路径不对（`@/components/xxx.vue` 对应 `src/components/xxx.vue`）

### 9.4 推送时报错「冲突」

说明云端有别人新推的修改，和你本地的冲突了。参考第 6.6 节「情况三」处理。如果不确定怎么选，截图发给尹辰。

### 9.5 发 PR 时找不到自己的分支

确认你已经把分支推送到 GitHub 了（`git push`）。用 GitHub Desktop 的话，确认点过 **Push origin** 按钮。推送后刷新 GitHub 仓库页面再试。

### 9.6 pnpm install 报错

可能是网络问题。试试切换 pnpm 镜像源：

```
pnpm config set registry https://registry.npmmirror.com
```

再重新 `pnpm install`。还不行就截图发给尹辰。

## 第十部分 遇到问题怎么办

1. **先看这份教程**——大部分操作步骤都写在上面了，特别是第六部分的 PR 流程速查
2. **截图发给尹辰**——遇到任何报错、看不懂的界面、PR 操作卡住，截图发飞书给尹辰，描述你刚才做了什么、想做什么
3. **不要自己瞎猜**——不确定的操作先问，特别是 Git 冲突、PR 合并这种不可逆的操作，不要乱点

记住：你不需要懂代码逻辑，你的核心任务是「把设计稿翻译成组件」。模板和规范都给你了，照着套就行。组长会全程指导你，有问题随时问。
